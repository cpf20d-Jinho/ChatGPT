# 보고서 전용 웹 편집 · v0.10.0

## 사용 순서
1. 앱에서 아동·보고 기간·프로그램을 선택하고 보고서 문장을 작성한다.
2. **보고서 웹 편집**을 누르고 기존 서버 접속 토큰을 입력한다. Groq 키는 필요 없다.
3. 전송할 여섯 항목과 수신처를 확인하고 동의한 뒤 링크를 만든다.
4. 같은 기기에서 열거나 신뢰하는 본인 컴퓨터로 링크를 전달한다. 링크를 가진 사람은 해당 서술을 읽고 수정할 수 있다.
5. 웹에서 수정 내용을 저장한다. 앱에서 **웹 수정본 검토 → 검토한 여섯 항목 적용**을 누른다.
6. **링크 종료 및 임시본 삭제** 후 앱의 전체 보고서를 다시 검토하고 PDF를 생성한다.

## 편집 범위
도전적 행동 변화, 종합 현황, 강점과 주요 변화, 치료사 종합 소견, 가정에서 함께 하기, 다음 목표. 각 12,000 UTF-16 코드 단위 이내.

프로필·생년월일·수업 원자료·그래프·표지·서명·참고 메모는 API에 없다. 자유 서술에 직접 입력한 개인정보를 자동 제거하는 기능은 아니므로 사용자가 전송 전에 확인한다. AI 전송 API와 완전히 별도로 작동하며 Groq를 호출하지 않는다.

## 보관 및 권한
- 현재 Render 무료 서버의 메모리에 AES-256-GCM 암호문만 기본 1시간 보관한다. 편집 화면에서 30분씩 연장할 수 있으나 사용자 서버 토큰의 만료 시각을 넘길 수 없다. 실제 접근 만료는 요청 즉시 적용하고 메모리 정리는 최대 10초 간격이다.
- 생성에는 기존 만료되는 사용자 서버 토큰과 `encrypted-edit-v1` 동의 헤더가 필요하다. 이후 접근은 해당 보고서의 무작위 256비트 capability로 제한한다. 계정 토큰만으로 개별 편집 내용을 읽을 수 없다.
- 앱 CryptoKit과 브라우저 Web Crypto를 사용한다. 12바이트 nonce + ciphertext + 16바이트 tag를 base64로 전송한다. 키는 URL fragment에만 포함하여 서버로 전송하지 않는다.
- 브라우저는 fragment를 현재 기록에서 제거하고 쿠키·로컬 스토리지·외부 스크립트·분석 서비스를 사용하지 않는다. 링크 전달 과정의 사본이나 브라우저 동기화 기록까지 삭제한다고 보장하지 않는다. 웹 코드 배포자와 접속 기기는 신뢰해야 한다.
- 계정당 3개·서버 전체 32개 방으로 제한한다. JSON 최대 600,000바이트, 방별 분당 60요청. 서버는 본문·키·capability를 로그하지 않는다. 플랫폼 접속 로그는 별도 정책이 적용된다.
- 웹 동시 저장은 revision 비교 후 409로 거부한다. 앱의 원본 서술 또는 집계 fingerprint가 변경되면 자동 덮어쓰지 않는다. 앱 반영 전 기기 파일 저장이 실패하면 적용을 중단한다.
- 무료 서버 중지·재시작·재배포 시 임시본은 소실된다. 앱 원본은 유지되며 서버 백업 기능은 없다. 앱 종료 후에는 링크를 복구할 수 없으므로 새 링크가 필요하다. 브라우저 임시본 다운로드는 평문 텍스트 파일이다.

## 제출 전 확인
새로운 선택적 전송을 공개 개인정보 방침과 App Store 개인정보 설명에 반영해야 한다. 현재 문서는 구현 설명이며 운영자·연락처·서비스 계약의 확정을 대체하지 않는다. 시스템 CryptoKit을 통한 암호화 사용을 포함하여 최종 바이너리의 수출 규정 질문을 확인한다.
