## 데이터 구조와 호환성

- 기존 `Child -> Program -> Level -> Target -> TherapySession -> Trial` 구조로 수행 기록을 표현할 수 있어 임상 모델/SwiftData 스키마는 변경하지 않는다.
- `TherapySession`은 **과제별 하루 기록**이다. 이를 합산하여 총 방문 회기로 표시하면 중복된다. 방문 세션 모델이 없으므로 총 회기는 직접 확인 입력한다. 하루 여러 방문을 임의로 복원하지 않는다.
- 구조화된 `ReportDocument`를 유지하며 `ReportGoal.objective`와 초안의 `supportNeeds`, `notesByProgram`, `totalSessions`, `logoPNG`를 추가한다. 추가 필드는 optional이므로 이전 JSON 초안이 열려야 한다.
- 이전 `currentStatus` 문장을 개요, `majorChanges`를 향상, `behavior`를 행동 변화, `therapistOpinion`을 전체 해석, `nextGoals`를 향후 계획에서 직접 검토·편집한다. `homePractice`는 공통 가정 연계로 보존한다. 원문을 자동 재작성하지 않는다.
- 기존 기관장·서명·평가군 등 초안 필드도 삭제하지 않는다. 새 PDF에는 원본이 요구하지 않는 별도 표지·균형분석·종합 성장·서명 페이지를 자동 추가하지 않는다.
- 신규 수행 보고서의 서술은 모두 직접 편집 가능하다. 이전 AI 설정이 켜져 있어도 편집을 잠그지 않는다. 새 작성 흐름은 AI 자동 작성 요청을 노출하지 않는다.
- 웹 편집은 기존 6개 필드 계약을 유지한다. 지원 필요·개별 노트·로고·총 회기는 전송하지 않고 기기에서 편집한다. 웹 수정본 적용 시 이 필드들을 보존한다. 서버 배포 변경은 필요하지 않다.
- 프로그램 선택 해제는 저장된 노트를 삭제하지 않는다. 선택 기간 밖 과제는 목록에서 제외한다. 유효한 완료 데이터가 없는 프로그램은 집계/출력 대상에서 제외하는 기존 규칙을 유지한다.
- 실제 로고·임상 정보와 예시 PDF의 수치는 기본 데이터로 복사하지 않는다.

## 검증

- Node 템플릿 검사: 네 구역 순서, 13개 프로그램과 22개 레벨, 각 그래프·노트 연결, 목표 설명, 생활연령, 미입력 처리, HTML 이스케이프, 불규칙 날짜 등간격·레벨 선 분리.
- 서버/개인정보 Node 회귀 검사: 17개 통과.
- Chrome 합성 PDF: 13개 프로그램 기본 출력 8페이지, 긴 목록·개별 노트·해석 추가 시 15페이지. 이것은 관측 결과이며 페이지 수 요구조건이 아니다. 끝 문구, 긴 목록/노트 끝 문구의 존재를 확인한다.
- Swift 테스트 추가: 기존 초안 읽기, 새 항목 저장 복원, 웹 수정본 적용 시 새 필드 보존, 치료일 중복 제거, 기간 밖 과제 제외, 목표 설명 대응.
- Xcode와 Swift Playgrounds 소스/리소스를 동기화한다.
- Windows에는 Swift/Xcode 및 `xcrun`이 없어 로컬 iOS 빌드·시뮬레이터 검증은 불가능하다. 최신 변경의 iOS 검증 결과는 해당 GitHub Actions 실행 결과로 확인해야 한다. 과거 버전의 성공을 새 버전 결과로 재사용하지 않는다.

## 남은 범위

정확한 방문 회기 자동 집계는 실제 방문을 나타내는 별도 데이터 모델이 필요하다. 현재는 추정하지 않고 직접 입력한다. XLSX/HWPX 출력은 기존 계획 상태이며 이번 변경은 앱 입력과 HTML/PDF 출력에 적용한다.
