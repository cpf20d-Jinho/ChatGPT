# ABAProgress v0.6 치료 현장 시나리오 검증

검증 범위: 치료사의 실시간 Trial 기록, 중단/재개, 오류 입력 복구, 날짜별 기록 검토, 과거 데이터 수정, Level 자동 판정, 보고서 데이터 무결성.

> 현재 Linux 환경에서는 iOS/iPadOS Simulator를 실행할 수 없으므로, 본 검증은 코드 경로 분석 + 순수 Swift 시뮬레이션 테스트 + SwiftUI Expert 기준 정적 UX audit로 수행했습니다. 실제 터치 감각/화면 렌더링/앱 백그라운드 복원은 iPad Swift Playgrounds에서 최종 확인해야 합니다.

## 2. 기록 확인/수정 시나리오

| # | 상황 | 기대 동작 | 검증/개선 결과 |
|---|---|---|---|
| 1 | 특정 날짜에 여러 아동 치료 | 날짜 → 아동별로 구분해서 확인 | 기존 구조 유지 |
| 2 | 해당 날짜에 미완료 기록 존재 | 검토자가 누락을 즉시 알아야 함 | 캘린더 요약에 `미완료` 수 추가 |
| 3 | 과거 Trial 한 개 수정 | 신규 입력과 동일한 UI에서 수정 | 기존 구조 유지 + 과거 수정 모드 표시 |
| 4 | 과거 수정 중 잘못 한 번 더 탭 | 직전 수정 취소 | Undo 추가 |
| 5 | 잘못 생성된 Session | 삭제 가능해야 함 | 과거 기록 화면에 `이 기록 삭제` 추가 + 확인창 |
| 6 | 과거 완료 Session을 수정하여 L1 기준 미달 | 이미 진행된 L2/L3를 자동 삭제하면 안 됨 | 자동 rollback 금지 + Level 검토 경고 추가 |
| 7 | 과거 수정 후 보고서 생성 | 최신 원본 데이터 사용 | 그래프/보고서가 원본 Session을 다시 조회 |
| 8 | 미완료 Session이 보고서에 섞임 | 최종 보고서 통계에 포함되면 안 됨 | 화면/PDF 모두 완료 Session만 사용 |
| 9 | 보고서 기간에 미완료 Session 존재 | 누락 원인을 사용자가 알 수 있어야 함 | 보고서 상단 경고 추가 |
| 10 | 기록 수정 시간을 확인 | 최근 수정 여부를 확인 가능 | 과거 기록에 마지막 수정 시각/수정됨 표시 |
| 11 | 한 날짜에 Level 전환이 발생 | 프로그램 헤더가 L1 하나로 오표기되면 안 됨 | 기록된 Level들을 `L1, L2`처럼 복수 표시 |
| 12 | 월 이동 후 다른 달이 보이는데 선택일은 이전 달 | 화면과 선택 상태 불일치 방지 | 월 이동 시 선택일도 새 달로 이동 |
| 13 | 아동 또는 프로그램을 실수로 swipe delete | 즉시 전체 기록 삭제되면 안 됨 | 아동/프로그램 삭제 확인창 추가 |
| 14 | 같은 날짜에 기록 아동이 많음 | 원하는 아동을 빠르게 찾아야 함 | 날짜별 아동 검색 추가 |

## 4. 실제 기기에서 추가 확인할 항목

다음은 코드 시뮬레이션만으로 완전히 검증할 수 없습니다.

1. 치료 중 연속 탭 시 오입력률과 햅틱 체감
2. Long Press 0.55초가 실제 치료 속도에 적절한지
3. iPhone 작은 화면과 iPad 가로 화면에서 Trial 버튼 크기
4. Dynamic Type 최대 크기에서 버튼/헤더 잘림 여부
5. Swift Playgrounds에서 SwiftData 스키마 변경(v0.5 → v0.6) 마이그레이션
6. 앱 강제 종료/화면 잠금 직후의 마지막 입력 복원
7. VoiceOver 사용 시 Trial 순서와 상태 안내

실제 iPad에서 위 항목을 점검한 후 touch target/spacing/long-press duration을 조정하는 것이 최종 UX 검증 단계입니다.
